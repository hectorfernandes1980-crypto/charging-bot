# Charging bot — бесплатное размещение на Cloudflare

Бот бронирования двух зарядных мест: 09:00–14:00 и 14:00–19:00,
сегодня и шесть следующих дней. Команды сохранены из исходного Python-бота.
Реализация перенесена на JavaScript без библиотек выполнения: Cloudflare Worker
принимает webhook Telegram, D1 постоянно хранит участников, брони и диалоги администратора.
Компьютер после настройки можно выключать. Отдельный домен не нужен.

## 1. Подготовка

Понадобятся аккаунт Cloudflare, Node.js 22 или новее, Python 3 и токен существующего
бота из BotFather. Новый Telegram-бот не нужен. Токен не публикуйте и не кладите в код.

Распакуйте архив. В терминале перейдите в папку `charging-bot`, например на Mac:

```bash
cd ~/Downloads/charging-bot
npm install
npx wrangler login
```

Откроется браузер для входа в Cloudflare. Используйте Workers **Free**, не подключайте Paid.

## 2. Создание базы

```bash
npx wrangler d1 create charging-bot-db
```

Команда покажет `database_id` — скопируйте его вместо `REPLACE_WITH_DATABASE_ID`
в файле `wrangler.jsonc`. Сохраните binding **DB**, имя базы **charging-bot-db**.
Если Wrangler предложит самостоятельно изменить конфигурацию, проверьте, что
в `d1_databases` осталась ровно одна запись с этим binding и настоящим ID.

В `ADMIN_USER_ID` уже указан **209708667** из исходного кода. Убедитесь, что это ваш ID.
Администратор имеет доступ автоматически; остальные пользователи получают доступ через /add.
Часовой пояс — `Europe/Moscow`.

```bash
npx wrangler d1 migrations apply charging-bot-db --remote
```

Подтвердите применение миграции. Она создаёт таблицы без удаления существующих данных.

## 3. Перенос данных со старого бота (если уже есть брони)

Остановите старый бот на Railway и скачайте его актуальный `bookings.json`.
Если файл уже потерян, восстановить из одного `bot.py` брони и участников невозможно.
Если данных нет, пропустите импорт и добавьте участников заново через /add.

Положите JSON в папку проекта и выполните **до запуска нового бота**, на пустой базе:

```bash
python3 scripts/import_bookings.py bookings.json import.sql
npx wrangler d1 execute charging-bot-db --remote --file=import.sql
```

Скрипт переносит имена, участников и брони. Он выводит старый admin_id:
если отличается, исправьте ADMIN_USER_ID в конфигурации. SQL содержит персональные
данные — не публикуйте его. Повторно импортировать файл в работающую базу не нужно:
конфликтующая бронь вызовет ошибку, а не перезапишет новую бронь.

## 4. Размещение

```bash
npm run deploy
```

Cloudflare выдаст адрес вроде `https://charging-bot.your-name.workers.dev`.
При первом запуске может предложить выбрать поддомен workers.dev — задайте его.
Открытие адреса в браузере показывает `Charging bot is running.` Это только проверка
доступности обработчика; токен и базу проверяет следующий шаг и сообщение /start.

## 5. Подключение Telegram

Убедитесь, что старый Python-процесс остановлен. Затем:

```bash
python3 scripts/connect.py
```

Скрипт попросит адрес Worker и токен BotFather. Токен вводится скрыто:
отсутствие символов на экране нормально. Скрипт сохранит токен и случайный секрет
в Cloudflare Secrets, установит webhook и меню команд. Локально токен не сохраняется.
Не прерывайте скрипт между обновлением секретов и установкой webhook; при сбое
запустите его заново. Очередь входящих сообщений Telegram не удаляется.

На Windows используйте `python` вместо `python3`, если так установлен Python.

## 6. Проверка в Telegram

1. Отправьте /start с аккаунта администратора — должен появиться блок 👑.
2. Отправьте /book, выберите будущий день и свободный слот.
3. Проверьте /week: слот должен быть занят вами.
4. Отмените через /cancel и убедитесь, что место свободно.
5. Другой пользователь отправляет /start и получает свой числовой ID.
6. Администратор отправляет /add, затем этот ID отдельным сообщением.
7. Проверьте, что два участника не могут занять один слот.

## Поведение и исправления

- /start, /week, /today, /book, /cancel; администратор: /add, /remove, /list.
- /abort прекращает ввод ID, /id показывает ID. Любая новая команда завершает старый диалог.
- Диалоги администратора хранятся в D1 и действуют 15 минут.
- Доступ проверяется и для команд, и для кнопок. Бот работает в личных чатах.
- Даты и окончание слота проверяются при нажатии. Уже начавшийся, но не закончившийся
  слот можно бронировать — это намеренное правило. Например, в 10:00 доступен слот 09:00–14:00.
- Уникальный ключ базы `(дата, место, слот)` не даёт создать две брони одновременно.
- Повторно доставленный Telegram update не повторяет изменения в базе: транзакционные
  квитанции хранятся семь дней. Ответы Telegram при сетевых повторах могут дублироваться;
  гарантии ровно одной доставки сообщения нет.
- При удалении участника его имеющиеся брони **сохраняются**, как в исходном боте.
  Поэтому перед удалением попросите его отменить ненужные брони. Администратор не может
  отменять чужую бронь текущими командами.
- Старые даты очищаются при следующем обращении участника, без фонового процесса.
- При сетевой ошибке webhook отвечает 500, чтобы Telegram повторил доставку.
- Проверяется секрет webhook. Токен и содержимое сообщений не пишутся в логи.

## Стоимость и ограничения

Проверено по документации 9 ноября 2026:
Workers Free — 100 000 запросов/сутки, 10 мс CPU на вызов; D1 Free —
5 млн прочитанных и 100 000 записанных строк/сутки, 5 ГБ общего хранения.
Запросы одного пользователя могут затрагивать несколько строк базы.
Ожидание сети не входит в CPU. При исчерпании бесплатных квот операции могут
возвращать ошибки до сброса квоты. Это не пробный тариф, но условия могут меняться.
Для двух мест и небольшой группы запас большой; реальную CPU-нагрузку нужно
посмотреть в панели Workers после запуска. Гарантии непрерывной работы бесплатный
вариант не даёт. Платные планы и автопереход на них проект не настраивает.

Официальные ссылки:

- https://developers.cloudflare.com/d1/platform/pricing/
- https://developers.cloudflare.com/d1/reference/migrations/
- https://core.telegram.org/bots/api#setwebhook

## Обновление, резервная копия, диагностика

После изменения `src/worker.js` или настроек:

```bash
npm test
npm run deploy
```

Секреты и данные D1 при обычном deploy сохраняются. При изменении адреса Worker
повторите `python3 scripts/connect.py`.

Сделать резервную копию (храните приватно):

```bash
npx wrangler d1 export charging-bot-db --remote --output=backup.sql
```

Если нет ответа:
- Проверьте настоящий database_id, binding DB и применение миграции с `--remote`.
- Проверьте ADMIN_USER_ID и наличие двух Secrets в настройках Worker.
- Откройте Workers → charging-bot → Logs или выполните `npx wrangler tail`.
- Повторите connect.py, если адрес или секреты менялись.
- Проверьте, что старый процесс на Railway остановлен.

Для возврата к Python сначала отключите webhook через Telegram Bot API `deleteWebhook`,
затем запускайте polling. Данные после переноса автоматически обратно в JSON не синхронизируются.

## Что проверено до передачи

Автотесты выполняют обработчики на Node.js с настоящей SQLite через адаптер D1
и имитацией Telegram API. Проверяются права, конфликт броней, отмена чужого слота,
повтор update после отмены, некорректные кнопки, московская полночь и защита webhook.
Также прошли сборка `wrangler deploy --dry-run`, применение миграции в локальной D1
и проверка импорта старого JSON. Это не заменяет проверку в настоящем Cloudflare и Telegram: для неё нужны ваш
аккаунт и токен. Проект не считается размещённым до выполнения шагов выше.
